Preface and Learning Outcomes

An operating system (OS) is one of the most important components of a computer system. It acts as a bridge between the computer's hardware and the applications used by people. Without an operating system, users would need to manage hardware operations directly, making ordinary computing difficult.

This book explains the major operating system concepts in student-friendly language. Each chapter introduces the basic idea, explains important concepts, gives examples and provides questions for revision. The book is intended to support introductory college-level study. Students should also follow their institution's syllabus and practical requirements.

What you will learn

  • Understand the role, goals and functions of an operating system.
  • Explain OS structures, services and system calls.
  • Understand processes, threads and CPU scheduling algorithms.
  • Study synchronization, deadlocks and resource allocation.
  • Learn memory management, paging and virtual memory.
  • Understand file systems, storage scheduling and device management.
  • Learn introductory Linux and Windows concepts.
  • Understand security, virtualization and modern operating environments.
How to study: Read the explanation first, write definitions in your own words, draw diagrams where appropriate, solve numerical examples step by step and then attempt the end-of-chapter questions without looking at the text.
Preface

Chapter 1: Introduction to Operating Systems

1.1 Meaning of an Operating System

An operating system is system software that manages computer hardware and software resources and provides common services to applications. It controls how programs execute, how memory is used, how files are stored and how devices communicate with the computer.

When a user opens a web browser, for example, the operating system creates or manages the process, allocates memory, schedules processor time, communicates with input devices and supports network operations. The application does not need to control each hardware component directly.

1.2 Why is an Operating System Needed?

A computer contains many resources, including the CPU, RAM, storage, keyboard, display and network interface. Several applications may need these resources at the same time. The operating system coordinates access so that applications can work efficiently without independently managing every hardware detail.

  • Convenience: Provides a usable environment for running applications.
  • Efficiency: Helps allocate CPU time, memory and devices.
  • Resource sharing: Coordinates competing requests for resources.
  • Reliability: Detects and handles many errors and exceptional conditions.
  • Security: Supports user accounts, permissions and isolation.
  • Abstraction: Hides many low-level hardware details behind simpler interfaces.

1.3 Main Functions of an OS

Process management

The OS creates, schedules and terminates processes. It allocates CPU time and coordinates communication between processes where required.

Memory management

The OS tracks which memory areas are in use, allocates memory to programs and releases memory when it is no longer needed. Modern systems also use virtual memory to provide each process with a managed address space.

File management

The OS organises stored information into files and directories. It supports operations such as creating, reading, writing, renaming and deleting files, subject to permissions.

Device management

The OS coordinates hardware devices through device drivers, interrupts, buffering and other mechanisms.

Security and protection

The OS helps verify identities, enforce access permissions and isolate processes. These mechanisms reduce the chance that one user or application can improperly affect another.

1.4 Components of a Computer System

  1. Hardware: CPU, memory, storage and input/output devices.
  2. Operating system: Manages hardware and provides services.
  3. Application programs: Browsers, editors, games and other software.
  4. Users: People or other systems interacting with the computer.

1.5 Kernel and Shell

The kernel is the central part of an operating system. It manages privileged operations such as process scheduling, memory management and communication with hardware. A shell is an interface through which a user can interact with system services. A shell may be command-line based or part of a graphical environment.

Example: When you save an assignment in a text editor, the application requests a file operation. The OS checks the request, coordinates storage access and reports whether the operation succeeded.

Chapter 2: Operating System Structure and Architecture

2.1 What is OS Architecture?

Operating system architecture describes how the major parts of an operating system are organised and how they communicate. A well-designed structure helps developers maintain the system, isolate faults and define clear interfaces between components.

2.2 Monolithic Structure

In a monolithic design, many core OS services operate within one large kernel address space. These services may include file systems, device drivers, memory management and scheduling. Communication between components can be efficient because they share the kernel environment.

A disadvantage is that a fault in a privileged component can affect the wider system. Large monolithic kernels can also be difficult to maintain if their internal boundaries are poorly designed.

2.3 Layered Structure

A layered OS divides functionality into levels. Each layer uses services from lower layers and provides services to higher layers. This organisation can simplify design and testing because each layer has a defined responsibility.

However, some operations may pass through several layers, introducing overhead. It can also be difficult to place every feature neatly into a single layer.

2.4 Microkernel Structure

A microkernel keeps a relatively small set of essential functions in kernel space. Other services may operate as separate processes outside the kernel. This design can improve fault isolation and modularity, although communication between separate services may introduce additional overhead.

2.5 Modular Structure

A modular kernel has a core that can work with separately organised modules. Modules may provide device drivers, file systems or other capabilities. This approach combines a central kernel with the flexibility of adding or removing supported components.

2.6 Hybrid Architecture

A hybrid design combines ideas from multiple architectural approaches. Real-world operating systems often use a mixture of techniques rather than following one textbook model perfectly.

2.7 Booting Process

Booting is the process of starting a computer and loading its operating system. Firmware performs early hardware initialisation, selects a boot device and starts a bootloader. The bootloader loads the kernel, which initialises core facilities and starts the remaining system services.

Example: When a laptop is switched on, firmware starts first, the bootloader selects the operating system and the kernel begins managing hardware and starting system services.

Chapter 3: Types of Operating Systems

3.1 Batch Operating System

A batch operating system collects jobs and processes them in groups. Users submit work, and the system executes jobs according to its scheduling and resource policies. Batch processing is useful when immediate interaction is not required.

Example: Large groups of payroll calculations or scheduled data-processing tasks may be handled in batches.

3.2 Multiprogramming Operating System

Multiprogramming keeps several jobs in memory. If one job waits for an input/output operation, the CPU can execute another ready job. This improves CPU utilisation compared with a system that leaves the processor idle during every I/O wait.

3.3 Multitasking Operating System

Multitasking allows several applications to make progress during the same period. The OS switches CPU execution between tasks quickly, creating the experience that applications are running together. On a multicore computer, some tasks may also run in parallel.

3.4 Time-Sharing Operating System

Time-sharing systems allocate small CPU time intervals to interactive users or processes. Scheduling is designed to provide responsive access while sharing the processor among competing tasks.

3.5 Multiprocessing Operating System

A multiprocessing system uses multiple processors or CPU cores. Depending on the workload and software, tasks may execute in parallel, increasing throughput or reducing completion time.

3.6 Real-Time Operating System

A real-time OS is designed to respond within specified timing constraints. Correctness may depend on both the result and when the result is produced.

  • Hard real-time: Missing a critical deadline is considered unacceptable under the system's requirements.
  • Soft real-time: Missing a deadline reduces quality or usefulness, but occasional misses may be tolerated.

Real-time systems are used in industrial controllers, robotics and certain embedded applications. They require careful timing analysis and predictable resource management.

3.7 Distributed and Network Operating Environments

A network operating system provides facilities for computers that communicate over a network, such as shared files, authentication or remote services. A distributed system coordinates computation and resources across multiple machines. The terms are related, but they describe different system goals and designs.

3.8 Embedded and Mobile Operating Systems

Embedded operating systems run on devices built for specialised tasks, such as appliances, sensors and industrial equipment. Mobile operating systems support portable devices and must manage touch interfaces, wireless communication, power consumption, applications and privacy permissions.

Chapter 4: OS Services, System Calls and Modes

4.1 Operating System Services

An operating system provides a standard environment in which programs can run. Common services include user-interface support, program execution, input/output operations, file manipulation, communication, error detection, resource allocation, usage accounting and protection.

4.2 User Interface

A command-line interface accepts text commands. A graphical user interface provides windows, icons, menus and pointers. Both allow users to request operations, although they differ in presentation and interaction style.

4.3 System Calls

A system call is a controlled way for an application to request a service from the operating system kernel. Applications generally cannot perform privileged hardware operations directly. Instead, they use supported interfaces that allow the OS to validate and carry out requests.

4.4 Categories of System Calls

  • Process control: Create processes, wait for completion and terminate execution.
  • File management: Open, read, write and close files.
  • Device management: Request device operations or obtain device information.
  • Information maintenance: Read system time, process information or system attributes.
  • Communication: Exchange data between processes or across supported communication channels.
  • Protection: Manage permissions and access-related information.

4.5 User Mode and Kernel Mode

Modern processors provide execution privilege levels. User-mode applications operate with restricted privileges. Kernel-mode code can perform authorised privileged operations, such as managing memory mappings and device access.

When an application requests a system service, the system transitions through a controlled mechanism into the kernel. After the request is handled, execution returns to the application if appropriate.

4.6 Interrupts and Exceptions

An interrupt typically signals an event that requires processor attention, such as a hardware device completing an operation. An exception occurs because of a condition associated with instruction execution, such as an invalid operation or a page fault. The OS handles these events according to the processor architecture and system design.

Example: A text editor asks the OS to open a document. The OS checks access permissions, performs the required file operation and returns the result to the application.

Chapter 5: Processes and Process States

5.1 Program and Process

A program is a stored set of instructions. A process is an executing instance of a program. A process includes its execution state, memory mappings, allocated resources and other information required by the operating system.

5.2 Process States

  • New: The OS is creating the process.
  • Ready: The process can execute but is waiting for CPU allocation.
  • Running: The CPU is executing the process.
  • Waiting or Blocked: The process is waiting for an event, such as completion of an I/O operation.
  • Terminated: The process has finished or has been stopped.

A process can move from ready to running when scheduled. A running process may become blocked while waiting for an event, return to ready after preemption or finish and enter the terminated state.

5.3 Process Control Block

The Process Control Block (PCB) is an operating-system data structure containing information needed to manage a process. Its contents vary by system but commonly include the process identifier, process state, saved CPU context, scheduling information, memory-management information and resource-related details.

5.4 Context Switching

A context switch occurs when the CPU stops executing one process or thread and resumes another. The OS saves the current execution context and restores the context of the next scheduled task.

Context switching enables sharing of the CPU, but it has overhead because saving and restoring state consumes time. Frequent switching is not automatically better; the system must balance responsiveness and useful execution.

5.5 Process Creation and Termination

Processes may be created when a user launches an application, a system service starts work or another process requests creation through supported OS facilities. When a process finishes, the OS releases its resources and records any required completion status.

5.6 Interprocess Communication

Processes may need to exchange data or coordinate activities. Common interprocess communication (IPC) mechanisms include pipes, message queues, shared memory and network sockets. Shared memory can be efficient, but concurrent access often requires synchronisation.

Example: A browser may contain several processes for different responsibilities. The OS schedules them, manages their memory and helps isolate failures between components.

Chapter 6: CPU Scheduling Algorithms

6.1 Meaning of CPU Scheduling

CPU scheduling selects a process or thread from the ready queue for execution. Scheduling matters because many tasks may be ready while only a limited number of CPU cores are available.

6.2 Scheduling Criteria

  • CPU utilisation: The proportion of time the CPU is doing useful work.
  • Throughput: The number of completed processes per unit of time.
  • Turnaround time: Total time from arrival to completion.
  • Waiting time: Time spent waiting in the ready queue.
  • Response time: Time until the process first receives CPU service or produces its first response, depending on the stated definition.

6.3 First Come, First Served

FCFS executes processes in arrival order. It is straightforward and typically non-preemptive. However, a long job at the front of the queue can delay many shorter jobs, a problem often called the convoy effect.

6.4 Shortest Job First

SJF selects the ready process with the shortest expected next CPU burst. In ideal conditions, it minimises average waiting time for a known set of CPU bursts. In practice, the next burst must be estimated. A preemptive variant, Shortest Remaining Time First, can interrupt a process when a process with a shorter remaining time becomes ready.

6.5 Priority Scheduling

Priority scheduling selects a process based on its priority. The exact meaning of a higher numeric value depends on the system or question. Starvation can occur when low-priority processes are repeatedly delayed. Aging gradually increases a waiting process's priority to reduce this risk.

6.6 Round Robin

Round Robin assigns each ready process a time quantum. If the process does not finish during that interval, it is preempted and returned to the ready queue. A very large quantum makes the algorithm behave more like FCFS; a very small quantum increases context-switch overhead.

6.7 Important Formulas

Turnaround Time (TAT) = Completion Time − Arrival Time
Waiting Time (WT) = Turnaround Time − CPU Burst Time, for the standard single-CPU scheduling exercise without additional waiting categories.
Response Time (RT) = First CPU Start Time − Arrival Time

6.8 Worked Example: FCFS

Consider three processes that all arrive at time 0. Their CPU burst times are P1 = 5 ms, P2 = 3 ms and P3 = 2 ms. FCFS executes them in the order P1, P2, P3.

6.9 Preemptive and Non-Preemptive Scheduling

In preemptive scheduling, the OS can interrupt a running process and assign the CPU to another process. In non-preemptive scheduling, a process normally keeps the CPU until it finishes its current CPU burst or blocks. Preemption can improve responsiveness but introduces additional switching and coordination costs.

Chapter 7: Threads and Multithreading

7.1 What is a Thread?

A thread is a unit of execution within a process. A process can contain one thread or multiple threads. Threads belonging to the same process generally share the process's address space and resources, while each thread maintains its own execution state and stack.

7.2 Why Use Threads?

Threads can keep an application responsive while background work takes place. They may also share data more conveniently than separate processes. On systems with multiple CPU cores, suitable threads can execute in parallel.

  • Responsiveness: Background work need not always block the user interface.
  • Resource sharing: Threads can access common process data.
  • Lower overhead: Creating and switching threads can be less expensive than processes in many circumstances.
  • Parallelism: Independent work can use multiple cores when the system and application permit it.

7.3 User-Level Threads

User-level thread libraries manage thread operations largely in user space. They can offer low-cost thread management, but scheduling and blocking behaviour depend on the implementation and how it interacts with kernel-supported threads.

7.4 Kernel-Level Threads

Kernel-level threads are represented to and scheduled with support from the operating system kernel. This can allow different threads of a process to run on separate cores, subject to system resources and scheduling policies.

7.5 Multithreading Models

Common textbook models include many-to-one, one-to-one and many-to-many mappings between user threads and kernel threads. Each design has trade-offs involving concurrency, management overhead and blocking behaviour.

7.7 Challenges of Multithreading

Shared data must be handled carefully. Without synchronisation, threads may overwrite each other's changes or observe inconsistent state. Debugging concurrent programs can be difficult because the order of operations may vary from run to run.

Example: A media application may use one thread for interface updates and other threads for background tasks. Synchronisation helps ensure that shared state is updated safely.

Chapter 8: Process Synchronization

8.1 Meaning of Synchronization

Synchronization coordinates concurrent processes or threads that access shared data or resources. Its purpose is to maintain correct behaviour when multiple execution paths may operate at overlapping times.

8.2 Race Condition

A race condition occurs when the outcome depends on the timing or ordering of concurrent operations. For example, two threads might read the same account balance, calculate separate updates and overwrite one another's results if the update is not protected.

8.3 Critical Section

A critical section is the part of a program that accesses shared data or a resource that requires coordinated access. The surrounding code may include entry and exit sections that acquire and release the required protection.

8.4 Requirements of a Correct Solution

  • Mutual exclusion: Conflicting operations cannot enter the protected section simultaneously.
  • Progress: If the section is free and processes are requesting entry, the choice of the next entrant should not be postponed indefinitely under the stated assumptions.
  • Bounded waiting: A requesting process should not be bypassed indefinitely under the stated assumptions.

8.5 Mutex Locks

A mutex is a mutual-exclusion lock. A thread acquires the lock before accessing protected data and releases it after completing the operation. Correct lock usage is important: failing to release a lock may block other threads, while inconsistent locking can still allow race conditions.

8.6 Semaphores

A semaphore is a synchronisation primitive commonly described using wait and signal operations. A binary semaphore represents a limited two-state resource, while a counting semaphore can represent several available units of a resource. Exact semantics depend on the implementation.

8.7 Producer-Consumer Problem

In the producer-consumer problem, producers place items into a shared buffer and consumers remove them. The solution must prevent producers from inserting into a full buffer and consumers from removing items from an empty buffer. It must also coordinate simultaneous access to the shared buffer.

8.8 Deadlock and Starvation in Synchronization

Improper lock ordering can cause deadlock. Starvation occurs when a thread repeatedly fails to receive a resource or opportunity to proceed. Synchronisation design should consider lock ordering, fairness and the length of time locks are held.

Example: If multiple threads update a shared counter, a lock or an appropriate atomic operation can prevent updates from being lost.

Chapter 9: Deadlocks

9.1 Definition

A deadlock is a condition in which a set of processes cannot proceed because each is waiting for a resource or event that another process in the set must release or provide. Deadlocks commonly arise when processes hold resources while requesting additional resources.

9.2 Four Necessary Conditions

  • Mutual exclusion: At least one resource is usable by only one process at a time.
  • Hold and wait: A process holds one or more resources while waiting for additional resources.
  • No preemption: Resources cannot simply be taken away under the assumed resource model.
  • Circular wait: A circular chain of processes exists, with each waiting for a resource held by the next.

All four conditions must hold for a deadlock under this model. A prevention strategy can therefore eliminate at least one of them.

9.3 Resource Allocation Graph

A resource allocation graph represents processes and resource types. A request edge indicates that a process is waiting for a resource; an assignment edge indicates that a resource instance has been allocated. Cycles can help analyse deadlock possibilities, although interpretation depends on whether resource types have one or multiple instances.

9.4 Deadlock Prevention

Prevention changes system rules so that at least one necessary condition cannot hold. For example, a consistent global resource ordering can prevent circular wait. Other approaches may require processes to request resources under stricter rules, although such restrictions can reduce resource utilisation.

9.5 Deadlock Avoidance

Avoidance considers each resource request and grants it only if the resulting state remains safe. A safe state is one in which there exists an order of process completion such that every process can obtain its remaining resources, finish and release resources for the next process.

9.6 Banker's Algorithm

The Banker's Algorithm is a resource-allocation avoidance algorithm. It uses information about available resources, current allocations and maximum declared needs to test whether a request leaves the system in a safe state. Its assumptions must match the resource-allocation problem being solved.

9.7 Detection and Recovery

A system may allow deadlocks to occur and periodically run detection procedures. Recovery options can include terminating selected processes or reclaiming resources where safe. The best option depends on the cost of restarting work, the importance of processes and the resource involved.

Chapter 10: Main Memory Management

10.1 Role of Memory Management

Main memory management tracks which areas of RAM are in use, assigns memory to processes and releases memory when it is no longer required. It also helps enforce protection between processes and supports the translation of program addresses into physical memory addresses.

10.2 Logical and Physical Addresses

A logical address is an address generated within a process's address space. A physical address identifies a location in main memory. Hardware and OS mechanisms translate addresses so that a process can use its address space without needing to know its physical placement.

10.3 Contiguous Allocation

In contiguous allocation, a process is assigned a continuous region of physical memory. Allocation policies select a suitable available block. This is easy to understand but can lead to fragmentation as processes are allocated and released.

10.4 First Fit, Best Fit and Worst Fit

  • First fit: Choose the first free block large enough for the request.
  • Best fit: Choose the smallest available block that can satisfy the request.
  • Worst fit: Choose the largest available block that can satisfy the request.

The effectiveness of these methods depends on the workload and how memory is managed. No policy is universally best for every situation.

10.5 Internal and External Fragmentation

Internal fragmentation is unused space inside an allocated block. External fragmentation occurs when free memory is separated into small non-contiguous regions, so a large contiguous request cannot be satisfied even though total free memory may be sufficient.

10.6 Swapping

Swapping traditionally refers to moving a process or parts of its memory between RAM and secondary storage. Modern systems use more complex virtual-memory mechanisms, but the underlying goal is to manage limited physical memory while supporting active workloads.

10.7 Memory Protection

Memory protection prevents a process from accessing memory it is not authorised to use. Hardware support, address-space isolation and OS policy work together to reduce accidental or unauthorised interference between programs.

Example: If a system has several applications open, memory management allocates RAM to their working data and reclaims memory as processes finish or release allocations.

Chapter 11: Paging and Segmentation

11.1 Paging

Paging divides a process's logical address space into fixed-size pages and physical memory into frames of the same size. Pages can be placed in different frames, so a process does not need one continuous physical memory region.

11.2 Page Tables

A page table records the mapping between a process's virtual pages and physical frames. Page-table entries may also contain status and protection information. Hardware support, such as a translation lookaside buffer (TLB), can speed up address translation by caching recent mappings.

11.3 Paging Address Translation

A virtual address can be divided into a page number and an offset. The page number is translated through the page table into a frame number. The offset identifies the position within the page and is retained when forming the physical address.

Illustrative calculation: Suppose page size is 1,024 bytes and a virtual address is 2,500. The page number is floor(2500 / 1024) = 2, and the offset is 2500 − (2 × 1024) = 452 bytes. The physical frame number depends on the page-table mapping.

11.4 Advantages and Limitations of Paging

Paging removes external fragmentation caused by the need to allocate one large contiguous block. However, the last page of a process may have unused space, causing internal fragmentation. Page tables also consume memory and address translation requires system support.

11.5 Segmentation

Segmentation divides a program into logical units, such as code, data, stack or separate modules. Segments have variable sizes. A logical address contains a segment identifier and an offset within that segment. The OS checks that the offset falls within the segment's permitted range.

11.7 Translation Lookaside Buffer

A TLB is a small, fast cache that stores recently used address translations. A TLB hit allows translation to proceed without consulting the page table in the usual way. A TLB miss requires additional translation work. Actual behaviour depends on the processor and OS design.

Chapter 12: Virtual Memory and Page Replacement

12.1 Meaning of Virtual Memory

Virtual memory gives a process a managed address space that can be larger than the physical memory currently available to it. The system keeps the required pages in RAM and may store other pages on secondary storage until they are needed.

12.2 Demand Paging

Demand paging loads a page into physical memory when the page is first needed rather than loading every page at process startup. This can reduce initial loading work and allow memory to be used more flexibly.

12.3 Page Fault

A page fault occurs when a process accesses a virtual page that is not currently mapped as required in physical memory. The OS checks the access, locates the needed page if the reference is valid, obtains a frame when necessary, updates mappings and resumes the process. An invalid access may instead result in an error or termination.

12.4 Page Replacement

If a page must be loaded and no suitable free frame is available, the OS may select a resident page for replacement. The choice of replacement policy affects page-fault frequency and performance.

12.5 FIFO

First In, First Out replaces the page that entered memory earliest. It is easy to implement using arrival order, but it does not consider how frequently or recently a page is used. Under certain reference sequences, increasing the number of frames can even increase FIFO page faults, a phenomenon known as Belady's anomaly.

12.6 LRU

Least Recently Used replaces the page that has not been accessed for the longest time in the past. It uses recent history as an estimate of future need. Exact LRU tracking can be costly, so systems may use approximations.

12.7 Optimal Page Replacement

The optimal policy replaces the page whose next use is farthest in the future. It provides a useful theoretical benchmark, but an operating system generally cannot know future references exactly.

12.8 Thrashing

Thrashing occurs when a system spends a large proportion of its time handling page faults and transferring pages rather than executing useful work. It can occur when the active working sets of processes exceed available physical memory.

12.9 Working Set and Locality

Programs often show locality: they repeatedly access a relatively small group of instructions and data over a period. A working-set approach estimates the pages a process actively uses. Understanding locality helps explain why virtual memory can work effectively despite limited RAM.

Chapter 13: File System Management

13.1 What is a File?

A file is a named collection of information stored on a storage device. It may contain a document, image, program, audio recording, database or other data. The OS provides operations for managing files while the file system organises their storage and metadata.

13.2 File Attributes

Common attributes include the file name, type, size, timestamps, owner, permissions and storage-related metadata. The exact attributes depend on the operating system and file system.

13.3 Basic File Operations

  • Create: Establish a new file entry.
  • Open: Obtain a handle or descriptor for accessing a file.
  • Read: Retrieve data from a file.
  • Write: Store or modify file data.
  • Close: Release an open file handle.
  • Rename: Change a file's name or directory entry.
  • Delete: Remove a file entry, subject to system rules.

13.4 Directory Structures

A directory organises files and can contain other directories. A tree structure supports nested folders. Directory paths identify a file's location within this structure. Absolute paths start from a defined root, while relative paths are interpreted from a current location.

13.5 File Allocation Methods

Contiguous allocation stores a file's blocks in consecutive locations, which supports efficient sequential access but can make growth difficult. Linked allocation connects blocks through pointers, allowing flexible growth but potentially making random access slower. Indexed allocation uses an index to identify a file's blocks, supporting direct access at the cost of index storage.

13.6 File System Examples

NTFS is widely used with Windows. ext4 is common on Linux systems. APFS is used in modern Apple operating systems. Different file systems vary in features such as permissions, journaling, maximum supported sizes and recovery behaviour.

13.7 Permissions and File Protection

Permissions define who may read, write, execute or otherwise access a file. Systems may support owner/group/other permissions, access-control lists and additional security mechanisms. Appropriate permissions help prevent accidental modification or unauthorised access.

13.8 Journaling and Reliability

Some file systems use journaling to record certain intended changes before applying them to the main file-system structures. This can improve recovery after an unexpected shutdown, though journaling does not replace backups and does not guarantee that every recent user-data change will be preserved.

Example: A student may create folders for DBMS, Operating Systems and Computer Networks. A directory structure keeps assignments organised, while file permissions can restrict modification of important files.

Chapter 14: I/O and Device Management

14.1 Input and Output Devices

Input devices provide information to a computer, while output devices present results. Examples include keyboards, mice, scanners, displays, speakers and printers. Storage and network devices also perform input/output operations.

14.2 Device Drivers

A device driver is software that enables the operating system to communicate with a particular device or device class. The driver translates OS requests into operations understood by the device and reports status or errors.

14.3 Device Controllers

A device controller is hardware that manages a device or a group of related devices. It may contain control registers, status registers and data buffers. The CPU and OS coordinate with the controller to perform operations.

14.4 Polling and Interrupts

Polling checks a device's status repeatedly. This can be simple but may waste CPU time if the device rarely needs attention. Interrupt-driven I/O allows a device to notify the processor when an event requires attention, reducing the need for continuous checking.

14.5 Direct Memory Access

Direct Memory Access (DMA) allows a controller to transfer data between a device and memory with reduced continuous CPU involvement. The CPU typically configures the transfer, and the device or controller reports completion according to the system design.

14.6 Buffering

A buffer is a temporary storage area used while data moves between components operating at different speeds. Buffering can smooth transfers, but it does not necessarily increase the speed of the slowest component.

14.7 Caching

A cache stores copies of selected data so that later accesses may be faster. Unlike a simple transfer buffer, a cache is intended to reduce the cost of repeated access to data. Cache consistency and invalidation must be managed appropriately.

14.8 Spooling

Spooling queues jobs for a device that handles one job or a limited number of jobs at a time. A print spooler, for example, stores submitted documents in a queue and sends them to the printer as it becomes available.

Chapter 15: Disk Scheduling

15.1 Introduction

Disk scheduling decides the order in which pending storage requests are serviced. Traditional disk-scheduling algorithms focus on reducing mechanical head movement on hard disk drives. Their benefits differ for solid-state drives, where mechanical seek time is not the same concern.

15.2 FCFS

First Come, First Served services requests in arrival order. It is straightforward and preserves arrival order, but the head may travel a long distance between consecutive requests.

15.3 SSTF

Shortest Seek Time First selects the request closest to the current head position. It can reduce movement compared with FCFS in some workloads, but requests far from the current position may wait for a long time.

15.4 SCAN

SCAN moves the head in one direction and services requests along the way. At the end of the scan range, the head reverses direction. It is sometimes described as an elevator algorithm.

15.5 C-SCAN

Circular SCAN services requests in one direction. After reaching the end of the scan range, it returns to the other end and continues in the same service direction. The return movement is usually treated differently from normal request servicing when calculating performance.

15.6 LOOK and C-LOOK

LOOK reverses direction at the last pending request rather than necessarily travelling to the physical end of the disk. C-LOOK similarly services requests in one direction and then jumps to the other end of the pending-request range.

15.7 Calculating Head Movement

For a given service sequence, total head movement is the sum of the absolute differences between consecutive cylinder positions. The starting head position and the direction or end-point assumptions must be stated when solving a numerical question.

Example: If the head moves from cylinder 40 to cylinder 70, the movement for that step is |70 − 40| = 30 cylinders. If the next request is at cylinder 55, the additional movement is |55 − 70| = 15 cylinders.

Chapter 16: Protection and Security

16.1 Protection and Security

Protection defines and enforces rules about which processes or users can access particular resources. Security is the broader effort to protect the system and its data against unauthorised access, misuse and disruption.

16.2 Authentication

Authentication verifies an identity. Common methods include passwords, security keys, smart cards and biometrics. Multi-factor authentication combines different categories of evidence to reduce reliance on one credential alone.

16.3 Authorization

Authorization determines what an authenticated user or process is permitted to do. A user may be allowed to read a document but not modify it, or may be allowed to manage system settings only through an authorised administrative account.

16.4 Access Control

Access control mechanisms enforce permissions for files, directories, processes and other resources. Access-control lists and role-based policies are examples of ways to express permissions.

16.5 Principle of Least Privilege

The principle of least privilege means that users and applications should receive only the permissions required for their tasks. Reducing unnecessary privileges limits the potential impact of mistakes or compromised accounts.

16.6 Malware and System Updates

Malware is software designed to perform unauthorised or harmful activities. Operating-system and application updates can address known vulnerabilities, improve reliability and add features. Updates should be obtained from trusted sources.

16.7 Backups and Recovery

Backups preserve copies of important data so that it can be restored after accidental deletion, hardware failure or certain security incidents. A backup strategy should consider frequency, storage location, access protection and periodic restoration tests.

16.8 Practical Security Practices

  • Use strong, unique passwords and multi-factor authentication where available.
  • Install security updates from trusted sources.
  • Use standard accounts for everyday tasks when practical.
  • Review permissions for shared files and applications.
  • Keep separate backups of important work.
  • Avoid opening suspicious attachments or installing unknown software.
Example: A college lab can provide students with standard accounts while reserving administrative privileges for authorised staff. This reduces accidental changes to shared computers.

Chapter 17: Linux Operating System

17.1 Introduction to Linux

Linux is an open-source operating system kernel used in many distributions. A Linux distribution combines the kernel with utilities, libraries, package-management tools and applications. Linux-based systems are widely used on servers, personal computers, embedded devices and cloud infrastructure.

17.2 Linux Directory Structure

Linux uses a hierarchical file system rooted at /. Common directories include /home for user files, /etc for system configuration, /var for changing data such as logs, and /tmp for temporary files. The exact contents and policies vary by distribution.

17.3 Basic Linux Commands

pwd       # Display the current directory

cd        # Change directory
mkdir     # Create a directory
touch     # Create an empty file or update timestamps
cat       # Display file contents
cp        # Copy files
mv        # Move or rename files
rm        # Remove files
whoami    # Display the current username

Commands may behave differently depending on permissions, shell and distribution. Before running a command that modifies or deletes data, check its arguments and the current directory.

17.4 Users and Permissions

Linux commonly represents basic file permissions using read (r), write (w) and execute (x) for the owner, group and other users. Ownership and permissions help control who can view, modify or execute files.

17.5 Package Management

Package managers install, update and remove software while managing dependencies. Different distributions use different package formats and tools. Software should be installed from trusted repositories or verified sources.

17.6 Linux in Servers and Cloud Computing

Linux is common in server environments because it supports networking, automation, remote administration and a broad range of server software. Administrators use shell commands and configuration tools to monitor services and manage resources.

Chapter 18: Windows Operating System

18.1 Introduction to Windows

Microsoft Windows is a family of operating systems commonly used on personal computers. It provides a graphical desktop, application support, device management, user accounts, networking and system administration facilities.

18.2 Graphical User Interface

The Windows graphical interface includes the desktop, Start menu, taskbar, windows and File Explorer. These components let users launch applications, switch between tasks and organise files without needing to type every command.

18.3 File and Folder Management

File Explorer allows users to browse drives, create folders, copy files, rename items and manage supported file properties. Organising work by subject and using descriptive names makes files easier to locate.

18.4 Processes and Services

Windows manages running applications and background services. Task Manager provides information about processes, performance and startup applications. Services may operate without a visible application window to support functions such as networking or system maintenance.

18.5 Device Management

Windows uses device drivers to communicate with hardware. Device Manager helps users inspect devices and their status. Driver problems can result from incompatible software, outdated drivers or hardware faults, so updates should be obtained from reliable sources.

18.6 User Accounts and Permissions

Windows supports different account types and access permissions. Administrative privileges allow additional system changes. Using appropriate permissions helps protect settings and files from unintended modification.

18.7 Windows Security and Maintenance

Built-in security tools, system updates, backups and recovery options help maintain system reliability. Users should keep software updated, protect account credentials and maintain backups of important documents.

Chapter 19: Virtualization, Containers and Cloud Computing

19.1 Virtualization

Virtualization represents computing resources as virtual resources. It allows multiple isolated virtual environments to share one physical computer, subject to the capabilities of the hardware and virtualization software.

19.2 Virtual Machines

A virtual machine (VM) behaves like a software-defined computer. It has virtual CPU, memory, storage and network devices and runs a guest operating system. VMs are useful for testing software, running different operating systems and separating workloads.

19.3 Hypervisors

A hypervisor creates and manages virtual machines.

  • Type 1 hypervisor: Runs directly on the host hardware.
  • Type 2 hypervisor: Runs as an application on a host operating system.

19.4 Containers

Containers isolate applications and their dependencies while generally sharing the host OS kernel. They often start quickly and use fewer resources than full virtual machines, although isolation properties and performance depend on the platform and configuration.

19.6 Cloud Computing

Cloud computing provides resources such as virtual machines, storage, networks and managed services over a network. Providers use operating systems, virtualisation, orchestration and monitoring tools to manage their infrastructure.

19.7 Benefits and Challenges

Virtualization can improve resource utilisation, simplify testing and make workloads easier to move between supported environments. Challenges include performance overhead, configuration complexity, security management and the need to monitor resource consumption.

Example: A student can use a virtual machine to practise installing Linux without replacing the laptop's primary operating system. Containers can be useful for packaging a web application and its dependencies.

Chapter 20: Case Studies and Revision

20.1 Case Study: A Student Computer

Consider a student who opens a browser, edits an assignment and plays a music file at the same time. The OS manages separate processes or threads, allocates memory, schedules CPU time and handles device operations. It also provides access to files and network connections while enforcing account permissions.

If the browser becomes unresponsive, the operating system may still allow the student to switch to another application. Process isolation and resource-management mechanisms help prevent some failures from affecting every application, although they cannot prevent all system-wide failures.

20.2 Case Study: Print Queue

When several students send documents to a shared printer, the operating system or print service places jobs in a queue. Spooling lets applications submit work without waiting for the printer to finish every earlier job. The service sends jobs to the printer as it becomes available.

20.3 Case Study: Running Out of Memory

When active applications require more physical memory than is available, the system may reclaim memory, reduce caches or move selected pages to storage. Excessive paging can slow the computer substantially. Closing unused applications and ensuring sufficient memory for the workload can help, but the appropriate solution depends on the cause.

20.4 Case Study: File Permissions

A college project folder may contain shared notes and private work. File permissions help decide which users can read or modify each item. Correct permissions, account security and backups work together to reduce accidental loss or unauthorised changes.

20.5 Key Concepts for Revision

  • Operating systems manage hardware resources and provide services to applications.
  • Processes represent executing programs; threads are execution units within processes.
  • CPU scheduling balances throughput, response time and fairness.
  • Synchronization protects shared data from conflicting concurrent operations.
  • Deadlocks involve circular resource dependencies under specific conditions.
  • Paging and virtual memory support managed address spaces.
  • File systems organise stored information and enforce access permissions.
  • Device drivers and I/O mechanisms coordinate communication with hardware.
  • Security depends on authentication, authorization, updates and backups.
  • Virtual machines and containers provide different approaches to isolation.

Glossary

  • Operating System: System software that manages hardware and provides application services.
  • Kernel: Core component of an operating system.
  • System Call: Controlled request for a service from the OS kernel.
  • Process: A program in execution.
  • Thread: A unit of execution within a process.
  • PCB: Process Control Block; stores process-management information.
  • Scheduling: Selecting work for CPU execution.
  • Context Switch: Saving one execution context and restoring another.
  • Race Condition: A result that depends on the timing of concurrent operations.
  • Semaphore: A synchronisation primitive.
  • Deadlock: A condition in which processes cannot proceed due to resource dependencies.
  • Paging: Dividing virtual memory into fixed-size pages and physical memory into frames.
  • Page Fault: An event that occurs when a required virtual page is not currently available in physical memory.
  • Virtual Memory: A technique for managing process address spaces using memory and storage.
  • Thrashing: Excessive paging that reduces useful execution.
  • File System: A method of organising and managing files.
  • Device Driver: Software that allows OS communication with hardware.
  • Interrupt: A signal that requests processor attention.
  • DMA: Direct Memory Access.
  • Authentication: Verification of identity.
  • Authorization: Determination of permitted actions.
  • Hypervisor: Software that manages virtual machines.
  • Container: An isolated application environment that typically shares the host kernel.
