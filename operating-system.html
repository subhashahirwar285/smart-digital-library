Preface

An Operating System (OS) is essential system software that manages computer hardware and software resources. It provides an interface between users, applications and computer hardware.

This textbook introduces operating system concepts in simple language. It covers operating system types, system calls, processes, CPU scheduling, threads, synchronization, deadlocks, memory management, virtual memory, file systems, device management and security.

How to use this book: Read each chapter, understand the examples, draw the required diagrams and practise the numerical problems related to CPU scheduling, page replacement and disk scheduling.

Learning Outcomes

  • Understand the purpose and functions of an operating system.
  • Differentiate between various operating system types.
  • Explain processes, threads and CPU scheduling algorithms.
  • Understand synchronization and deadlock handling.
  • Learn memory allocation and virtual memory techniques.
  • Understand file systems, disk scheduling and security.
  • Identify basic features of Linux and Windows.

Chapter 1: Introduction to Operating System

1.1 What is an Operating System?

An Operating System is system software that manages computer hardware, software resources and program execution. It acts as an interface between the user and the computer hardware.

1.2 Main Objectives

  • Convenience: Makes the computer easier to use.
  • Efficiency: Uses CPU, memory and devices effectively.
  • Resource Management: Allocates resources to applications.
  • Security: Helps protect data and system resources.

1.3 Main Functions of an OS

The operating system manages processes, memory, files, input/output devices, storage, security and communication between applications and hardware.

1.4 Components of a Computer System

A computer system includes hardware, the operating system, application programs and users. Hardware performs physical operations, while the OS coordinates the use of hardware resources.

1.5 Kernel

The kernel is the core component of an operating system. It manages important tasks such as CPU scheduling, memory management, device communication and system calls.

Practical Example / Application: When you open a browser, the OS allocates memory, schedules CPU time and manages network and display operations.

Chapter 2: Types of Operating Systems

2.1 Batch Operating System

A batch operating system collects similar jobs and executes them in batches without requiring continuous user interaction during execution.

2.2 Multiprogramming OS

Multiprogramming keeps multiple programs in memory so that the CPU can execute another program when one program waits for an input/output operation.

2.3 Multitasking OS

A multitasking operating system allows a user to work with multiple applications during the same period by sharing CPU time between tasks.

2.4 Time-Sharing OS

A time-sharing operating system divides CPU time into small intervals and gives multiple users or processes opportunities to execute.

2.5 Multiprocessing OS

A multiprocessing operating system uses two or more processors or CPU cores to execute tasks concurrently or in parallel.

2.6 Real-Time Operating System

A real-time operating system is designed to respond within specified timing constraints. It is used in industrial control, embedded devices and certain medical systems.

2.7 Distributed and Network OS

A network operating system supports computers connected through a network. A distributed system coordinates resources and work across multiple computers.

2.8 Embedded and Mobile OS

Embedded operating systems run on dedicated devices. Mobile operating systems, such as Android and iOS, support smartphones and tablets.

Practical Example / Application: A smartphone uses a mobile operating system, while an industrial controller may use a real-time operating system.

Chapter 3: OS Services and System Calls

3.1 Operating System Services

Operating systems provide services such as program execution, input/output operations, file management, communication, error detection, resource allocation and security.

3.2 User Interface

A user interface allows people to interact with a computer. A command-line interface accepts text commands, while a graphical user interface uses windows, icons, menus and pointers.

3.3 System Calls

A system call allows an application to request a service from the operating system kernel.

3.4 Types of System Calls

  • Process Control: Creating and terminating processes.
  • File Management: Opening, reading and writing files.
  • Device Management: Requesting device operations.
  • Information Maintenance: Obtaining system information.
  • Communication: Exchanging data between processes.
  • Protection: Managing access permissions.

3.5 User Mode and Kernel Mode

User mode restricts applications from directly performing privileged operations. Kernel mode allows the operating system to perform authorised operations that require elevated privileges.

Practical Example / Application: When an application saves a file, it requests file operations through operating system services rather than directly controlling the storage hardware.

Chapter 4: Process Management

4.1 What is a Process?

A process is a program in execution. It includes program instructions, current execution state, allocated resources and associated memory.

4.2 Program vs Process

A program is a set of stored instructions. A process is an active instance of a program that is being executed.

4.3 Process States

  • New: The process is being created.
  • Ready: The process is waiting for CPU allocation.
  • Running: The CPU is executing the process.
  • Waiting: The process is waiting for an event or I/O operation.
  • Terminated: The process has completed or stopped.

4.4 Process Control Block (PCB)

A PCB stores information about a process, including its process ID, state, CPU registers, scheduling information and memory-management details.

4.5 Context Switching

Context switching occurs when the CPU stops executing one process and switches to another. The OS saves the current process state and restores the next process state.

4.6 Process Operations

Common process operations include creation, scheduling, blocking, waking up and termination.

Practical Example / Application: When a music player and a web browser are both running, the OS manages their processes and shares CPU time between them.

1. Define process and PCB.

2. Explain the different process states.

Chapter 5: Process Scheduling

5.1 Meaning of CPU Scheduling

CPU scheduling is the process of selecting a ready process for execution by the CPU.

5.2 Scheduling Objectives

  • Increase CPU utilisation.
  • Increase throughput.
  • Reduce waiting time.
  • Reduce turnaround time.
  • Provide good response time.

5.3 First Come, First Served (FCFS)

FCFS executes processes in the order in which they enter the ready queue. It is simple but may produce long waiting times.

5.4 Shortest Job First (SJF)

SJF selects the process with the shortest expected CPU burst. It can reduce average waiting time when burst lengths are known or estimated.

5.5 Priority Scheduling

Priority scheduling selects a process according to its assigned priority. Low-priority processes may suffer starvation unless suitable measures are used.

5.6 Round Robin (RR)

Round Robin assigns each ready process a fixed time quantum. If a process does not finish during its quantum, it returns to the ready queue.

5.7 Preemptive and Non-Preemptive Scheduling

In preemptive scheduling, the OS can interrupt a running process to schedule another process. In non-preemptive scheduling, a process generally keeps the CPU until it finishes or blocks.

5.8 Scheduling Formulas

Turnaround Time = Completion Time − Arrival Time
Waiting Time = Turnaround Time − CPU Burst Time
Response Time = First CPU Start Time − Arrival Time

Practice Question

Three processes have burst times of 5, 3 and 2 milliseconds. Assuming all arrive at time 0, calculate their FCFS waiting times and average waiting time.

Chapter 6: Threads and Multithreading

6.1 What is a Thread?

A thread is a basic unit of CPU execution within a process. Threads in the same process typically share its code, data and resources while maintaining their own execution state and stack.

6.2 Single-Threaded Process

A single-threaded process has one thread of execution. It performs its tasks through that thread.

6.3 Multithreading

Multithreading allows a process to contain multiple threads that can perform different tasks concurrently.

6.4 Benefits of Threads

  • Improved responsiveness.
  • Resource sharing within a process.
  • Lower creation overhead in many systems compared with processes.
  • Potential parallel execution on multiple CPU cores.

6.5 User-Level and Kernel-Level Threads

User-level threads are managed largely by a user-space library. Kernel-level threads are managed and scheduled with operating system support.

6.6 Process vs Thread

Processes generally have separate address spaces, while threads within one process normally share an address space. Threads can communicate efficiently, but shared data requires careful synchronisation.

Practical Example / Application: A browser may use different threads for interface updates, background tasks and other activities so that one task does not unnecessarily block the whole application.

Chapter 7: Process Synchronization

7.1 Meaning of Synchronization

Process synchronization coordinates processes or threads that access shared data or resources.

7.2 Race Condition

A race condition occurs when a result depends on the unpredictable timing or order of concurrent operations.

7.3 Critical Section

A critical section is a part of a program where shared data or resources are accessed. Suitable controls help prevent conflicting operations.

7.4 Critical Section Requirements

  • Mutual Exclusion: Conflicting critical-section operations must not occur simultaneously.
  • Progress: The selection of the next process should not be postponed indefinitely when the section is free.
  • Bounded Waiting: A process should not wait indefinitely to enter its critical section under the stated assumptions.

7.5 Mutex Locks

A mutex provides mutual exclusion. A thread locks the mutex before accessing protected data and unlocks it afterward.

7.6 Semaphores

A semaphore is a synchronisation mechanism that uses operations commonly called wait and signal. Binary semaphores can support mutual exclusion, while counting semaphores can manage multiple available resources.

7.7 Producer-Consumer Problem

The producer-consumer problem involves producers adding items to a shared buffer and consumers removing them. Synchronization ensures that the buffer is not accessed incorrectly when full or empty.

Practical Example / Application: When multiple threads update the same account balance, synchronization helps prevent inconsistent results caused by simultaneous updates.

Chapter 8: Deadlocks

8.1 What is Deadlock?

A deadlock is a situation in which a group of processes cannot proceed because each process is waiting for a resource or event that another process in the group must release or provide.

8.2 Four Necessary Conditions

  • Mutual Exclusion: At least one resource cannot be shared simultaneously.
  • Hold and Wait: A process holds resources while waiting for others.
  • No Preemption: Resources cannot be forcibly taken away under the assumed model.
  • Circular Wait: Processes form a circular chain of resource dependencies.

8.3 Deadlock Prevention

Prevention designs the resource-allocation rules so that at least one necessary deadlock condition cannot hold.

8.4 Deadlock Avoidance

Avoidance checks whether granting a resource request would leave the system in a safe state. The Banker's Algorithm is a well-known example.

8.5 Deadlock Detection

Detection allows deadlocks to occur and uses system information to identify them.

8.6 Deadlock Recovery

Recovery may involve terminating selected processes or reclaiming resources using an appropriate recovery policy.

Practical Example / Application: Process A holds Resource 1 and waits for Resource 2, while Process B holds Resource 2 and waits for Resource 1. Neither can continue until the dependency is resolved.

Important Questions

2. Explain the four necessary conditions.

3. Differentiate deadlock prevention and avoidance.

Chapter 9: Memory Management

9.1 Introduction

Memory management controls the allocation and release of main memory for processes and the operating system.

9.2 Logical and Physical Addresses

A logical address is generated by the CPU for a process. A physical address identifies a location in main memory after address translation.

9.3 Contiguous Memory Allocation

Contiguous allocation assigns a continuous region of memory to a process. Common placement strategies include first fit, best fit and worst fit.

9.4 First Fit

First fit selects the first available memory block that is large enough for the request.

9.5 Best Fit

Best fit selects the smallest available block that can satisfy the request.

9.6 Worst Fit

Worst fit selects the largest available block that can satisfy the request.

9.7 Fragmentation

Internal fragmentation is unused space within an allocated block. External fragmentation occurs when free memory is split into separate small regions.

9.8 Paging

Paging divides logical memory into fixed-size pages and physical memory into fixed-size frames. A page table maps pages to frames.

9.9 Segmentation

Segmentation divides a program into logical units, such as code, data and stack. Segments can have different sizes.

Practical Example / Application: Paging allows a process's pages to occupy different physical memory frames rather than requiring the entire process to occupy one continuous block.

Important Questions

1. Explain paging and segmentation.

2. Differentiate internal and external fragmentation.

3. Explain first fit, best fit and worst fit.

Chapter 10: Virtual Memory

10.1 Meaning of Virtual Memory

Virtual memory allows a process to use an address space that may be larger than the available physical memory. The operating system and hardware keep the required portions of memory available as needed.

10.2 Demand Paging

Demand paging loads a page into physical memory when it is needed rather than loading every page at the start.

10.3 Page Fault

A page fault occurs when a process accesses a page that is not currently available in physical memory. The OS handles the fault and may load the required page from storage.

10.4 Page Replacement

When no suitable free frame is available, the OS may select an existing page for replacement.

10.5 FIFO Algorithm

First In, First Out replaces the page that has been in memory for the longest time according to its arrival order.

10.6 LRU Algorithm

Least Recently Used replaces the page that has not been accessed for the longest time in the past.

10.7 Optimal Algorithm

The optimal algorithm replaces the page whose next use is farthest in the future. It is mainly used as a theoretical benchmark because future references are not normally known in advance.

10.8 Thrashing

Thrashing occurs when a system spends excessive time handling page faults and moving pages instead of making useful progress.

Practical Example / Application: A computer can run applications whose combined virtual address spaces exceed physical RAM because only selected pages need to remain in RAM at any particular time.

Chapter 11: File System Management

11.1 What is a File?

A file is a named collection of information stored on a storage device. It may contain text, images, programs, documents or other data.

11.2 File Attributes

Common file attributes include name, type, size, location, timestamps, ownership and access permissions.

11.3 File Operations

Common operations include creating, opening, reading, writing, renaming, closing and deleting files.

11.4 Directory Structure

A directory organises files and other directories. Common structures include single-level, two-level, tree-structured and graph-based directories.

11.5 File Allocation Methods

  • Contiguous Allocation: File blocks occupy consecutive storage locations.
  • Linked Allocation: File blocks are connected through links.
  • Indexed Allocation: An index structure identifies the blocks belonging to a file.

11.6 File System Examples

NTFS is commonly associated with Windows. ext4 is used by many Linux systems. APFS is used in Apple's modern operating systems.

11.7 Permissions

File permissions control who can read, write or execute a file. Exact permission mechanisms depend on the operating system and file system.

Practical Example / Application: Folders help organise college assignments by subject, while file permissions can restrict who is allowed to modify important documents.

Chapter 12: I/O and Device Management

12.1 Input and Output Devices

Input devices provide data to the computer, while output devices present results. Examples include keyboards, mice, printers and displays.

12.2 Device Drivers

A device driver is software that allows the operating system to communicate with a particular hardware device.

12.3 Device Controllers

A device controller is hardware that manages a device or a group of devices and communicates with the CPU and operating system.

12.4 Interrupts

An interrupt signals that an event requires attention. The processor temporarily changes its execution flow to handle the event.

12.5 Polling

Polling involves checking a device or status condition repeatedly to determine whether an event has occurred.

12.6 Direct Memory Access (DMA)

DMA allows certain devices to transfer data to or from memory with reduced continuous CPU involvement.

12.7 Buffering and Spooling

Buffering temporarily stores data during transfer. Spooling queues jobs for a device, such as a printer, so that multiple requests can be managed in order.

Practical Example / Application: A print queue stores multiple print jobs so that the printer can process them one at a time.

Important Questions

Chapter 13: Disk Scheduling

13.1 Disk Scheduling

Disk scheduling determines the order in which pending storage requests are serviced. Traditional algorithms were designed largely around mechanical hard disks.

13.2 FCFS

First Come, First Served handles requests in arrival order. It is simple and fair by arrival order but may result in substantial head movement.

13.3 SSTF

Shortest Seek Time First selects the pending request closest to the current disk-head position. Some requests may wait a long time.

13.4 SCAN

The SCAN algorithm moves the disk head in one direction, servicing requests along the way, and then reverses direction.

13.5 C-SCAN

Circular SCAN services requests in one direction and then returns to the beginning of the disk range to continue servicing requests.

13.6 LOOK and C-LOOK

LOOK reverses at the last pending request in the current direction. C-LOOK services requests in one direction and then jumps to the other end of the pending-request range.

13.7 Performance Measurement

Total head movement can be calculated by adding the absolute differences between consecutive head positions in the service sequence.

Practical Example / Application: If a disk head moves from cylinder 40 to cylinder 70, the head movement for that step is |70 − 40| = 30 cylinders.

Important Questions

1. Explain FCFS and SSTF.

2. Differentiate SCAN and C-SCAN.

3. How is total disk-head movement calculated?

Chapter 14: Protection and Security

14.1 Operating System Security

Operating system security protects system resources, accounts, programs and data from unauthorised access or misuse.

14.2 Authentication

Authentication verifies a user's identity using methods such as passwords, security keys or biometrics.

14.3 Authorization

Authorization determines which operations an authenticated user or process is permitted to perform.

14.4 Access Control

Access control restricts access to files, devices, applications and other resources according to defined permissions.

14.5 User Accounts and Privileges

Standard accounts usually have limited permissions. Administrative accounts can perform additional system-management tasks.

14.6 Malware and Updates

Malware is software designed to perform unauthorised or harmful actions. Security updates help address known vulnerabilities in operating systems and applications.

14.7 Security Best Practices

  • Use strong, unique passwords.
  • Install updates from trusted sources.
  • Use least-privilege accounts.
  • Enable appropriate security protections.
  • Back up important files regularly.
  • Avoid opening suspicious attachments.
Practical Example / Application: A college computer lab can use separate student and administrator accounts to prevent ordinary users from changing important system settings.

Important Questions

1. Differentiate authentication and authorization.

2. Explain access control.

3. List important operating system security practices.

Chapter 15: Linux and Windows Operating Systems

15.1 Linux

Linux is an open-source operating system kernel used in many distributions. Linux-based operating systems are common on servers, personal computers, embedded devices and cloud infrastructure.

15.2 Windows

Microsoft Windows is a family of operating systems that provides a graphical desktop environment, application support, device management and system administration tools.

15.3 Linux File System

Linux uses a hierarchical directory structure. The root directory is represented by /. Directories such as /home, /etc and /var have commonly used purposes.

15.4 Basic Linux Commands

pwd       # Show current directory
ls        # List directory contents
cd        # Change directory
mkdir     # Create a directory
touch     # Create an empty file
cat       # Display file contents
cp        # Copy files
mv        # Move or rename files
rm        # Remove files

Commands may behave differently depending on permissions, distribution and shell configuration. Review a command before running it, especially if it deletes files.

15.5 Linux Permissions

Linux commonly represents permissions using read (r), write (w) and execute (x) for the owner, group and other users.

15.6 Windows Features

Windows supports a graphical interface, file management, user accounts, device drivers, process management and administrative tools.

15.7 Comparison

Linux distributions often offer extensive customisation and open-source software. Windows commonly provides broad support for commercial desktop applications. The best choice depends on the user's requirements.

Practical Example / Application: A student can use Linux terminal commands to create folders and manage files, while Windows File Explorer offers a graphical way to perform similar tasks.

Important Questions

Chapter 16: Virtualization and Modern Operating Systems

16.1 Virtualization

Virtualization allows computing resources to be represented as virtual resources. It can enable multiple isolated virtual machines to run on the same physical computer.

16.2 Virtual Machine

A virtual machine is a software-defined computer that runs its own operating system and applications within a virtualized environment.

16.3 Hypervisor

A hypervisor creates and manages virtual machines.

  • Type 1: Runs directly on the host hardware.
  • Type 2: Runs as an application on a host operating system.

16.4 Containers

Containers isolate applications and their dependencies while sharing the host operating system kernel. They generally have less overhead than full virtual machines.

16.5 Cloud Computing

Cloud computing provides computing resources such as virtual machines, storage, networks and managed services over a network.

16.6 Embedded Operating Systems

Embedded operating systems are designed for specialised devices such as appliances, industrial controllers and electronic equipment.

16.7 Mobile Operating Systems

Mobile operating systems manage smartphone hardware, applications, connectivity, permissions and battery use.

Practical Example / Application: A student can use a virtual machine to practise installing Linux without replacing the main operating system on the laptop.

Important Questions

1. Define virtualization.

2. What is a hypervisor?

3. Differentiate virtual machines and containers.

4. Explain the role of operating systems in cloud computing.

Glossary

  • Operating System: Software that manages hardware and system resources.
  • Kernel: Core component of an operating system.
  • Process: A program in execution.
  • Thread: A unit of execution within a process.
  • PCB: Process Control Block; stores process information.
  • Scheduling: Selecting a process for CPU execution.
  • Context Switching: Saving one execution state and restoring another.
  • Deadlock: A condition in which processes cannot proceed because of resource dependencies.
  • Semaphore: A synchronization mechanism.
  • Paging: Dividing memory into pages and frames.
  • Virtual Memory: A memory-management technique that provides a virtual address space.
  • Page Fault: An event caused when a required page is not currently in physical memory.
  • Thrashing: Excessive paging that reduces useful system work.
  • File System: A method of organising and managing stored files.
  • Device Driver: Software that enables OS communication with hardware.
  • Interrupt: A signal that requests processor attention.
  • DMA: Direct Memory Access.
  • Hypervisor: Software that manages virtual machines.
  • Authentication: Verification of identity.
  • Authorization: Determination of permitted actions.
