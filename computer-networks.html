Preface

Computer networking is an important subject in computer science. It explains how computers and other digital devices communicate, exchange information and share resources.

This textbook introduces networking concepts in a structured sequence, starting with basic communication and progressing to network models, devices, IP addressing, routing, transport protocols, application protocols, wireless networks and security.

How to use this book: Read the chapters in order, practise drawing network diagrams, compare protocols, and use a computer or networking simulator to explore basic networking concepts.

Learning Outcomes

  • Understand the fundamentals of computer networks.
  • Identify network types, topologies and transmission media.
  • Explain the OSI and TCP/IP models.
  • Understand Ethernet, switching and IP addressing.
  • Learn subnetting, routing, TCP and UDP.
  • Understand DNS, HTTP, DHCP and other application protocols.
  • Identify basic network security and troubleshooting methods.

Chapter 1: Introduction to Computer Networks

1.1 What is a Computer Network?

A computer network is a group of interconnected computers and devices that communicate and share information or resources using communication links and agreed rules called protocols.

1.2 Objectives of Networking

  • Sharing files and information.
  • Sharing printers and other resources.
  • Supporting communication between users.
  • Providing access to remote services.
  • Improving resource utilisation and collaboration.

1.3 Basic Components

A network includes end devices, network interface cards, communication media, network devices and protocols. Examples of end devices are computers, smartphones, servers and printers.

1.4 Data Communication

Data communication is the exchange of data between devices through a transmission medium. Its basic components are sender, receiver, message, transmission medium and protocol.

1.5 Network Protocol

A protocol defines rules for communication, including message format, timing, addressing and how devices respond to received information.

1.6 Network Performance

Bandwidth describes a link's capacity. Throughput is the actual rate of successful data transfer. Latency is the time taken for data to travel between endpoints, and packet loss occurs when packets fail to reach their destination.

Practical Example / Application: When a laptop opens a website, it communicates with a remote server through one or more networks using several protocols.

Chapter 2: Network Types and Topologies

2.1 Personal Area Network (PAN)

A PAN connects personal devices over a short distance. Bluetooth connections between a phone and headphones are a common example.

2.2 Local Area Network (LAN)

A LAN connects devices within a limited area, such as a home, office, laboratory or college building.

2.3 Metropolitan Area Network (MAN)

A MAN connects networks across a city or a larger metropolitan area.

2.4 Wide Area Network (WAN)

A WAN connects networks across large geographical areas. The Internet is the most familiar example of a global network built from interconnected networks.

2.5 Network Topology

Topology describes how network devices and links are arranged physically or logically.

  • Bus: Devices share a common communication backbone.
  • Star: Devices connect to a central switch or hub.
  • Ring: Devices form a ring-shaped connection.
  • Mesh: Devices have multiple interconnections.
  • Tree: Devices are organised hierarchically.
  • Hybrid: Two or more topology types are combined.

2.6 Client-Server Network

In a client-server model, clients request services and servers provide them. Websites, email services and database applications commonly use this model.

2.7 Peer-to-Peer Network

In a peer-to-peer network, devices can share resources directly without relying entirely on a dedicated central server.

Practical Example / Application: A college computer laboratory commonly uses a star topology in which computers connect to a central network switch.

Important Questions

1. Differentiate LAN, MAN and WAN.

2. Explain star, bus, ring and mesh topologies.

3. Differentiate client-server and peer-to-peer networks.

Chapter 3: Network Devices and Transmission Media

3.1 Network Interface Card (NIC)

A NIC enables a device to connect to a network. Wired NICs use Ethernet connections, while wireless NICs provide Wi-Fi connectivity.

3.2 Hub

A hub repeats incoming signals to its other ports. It does not intelligently forward Ethernet frames based on destination MAC addresses.

3.3 Switch

A switch commonly operates at the data link layer and forwards Ethernet frames using MAC address information.

3.4 Router

A router forwards packets between different IP networks using routing information.

3.5 Modem

A modem performs signal conversion or modulation and demodulation appropriate to a communication technology. The exact role depends on the access network.

3.6 Wireless Access Point

A wireless access point allows Wi-Fi devices to connect to a local network.

3.7 Repeater and Bridge

A repeater regenerates or repeats signals to extend communication distance. A bridge connects network segments at the data link layer.

3.8 Transmission Media

  • Twisted Pair: Commonly used in Ethernet cabling.
  • Coaxial Cable: Used in some broadband and communication systems.
  • Optical Fibre: Carries data as light and supports high capacity over suitable distances.
  • Wireless Media: Uses radio waves or other electromagnetic signals.
Practical Example / Application: A home router may combine routing, switching and Wi-Fi access point functions in one device.

2. What is a network interface card?

Chapter 4: OSI Reference Model

4.1 Introduction

The Open Systems Interconnection (OSI) model is a seven-layer reference model used to understand network communication and organise networking functions.

4.2 The Seven Layers

  1. Physical Layer: Transmits raw bits through a physical medium.
  2. Data Link Layer: Handles frames, MAC addressing and link-level delivery.
  3. Network Layer: Handles logical addressing and packet routing.
  4. Transport Layer: Supports end-to-end transport, segmentation and reliability where provided.
  5. Session Layer: Describes session establishment and management functions.
  6. Presentation Layer: Describes data representation, translation, compression and encryption functions.
  7. Application Layer: Provides network-related services to applications.

4.3 Encapsulation

As data moves down the networking stack, each layer may add control information. At the receiving endpoint, the corresponding layers process and remove that information.

4.4 Protocol Data Units

Common terminology includes bits at the physical layer, frames at the data link layer, packets at the network layer and segments or datagrams at the transport layer.

4.5 Why the OSI Model is Important

The model helps students understand network functions, compare protocols and troubleshoot problems systematically.

Memory Tip: From bottom to top, the layers are Physical, Data Link, Network, Transport, Session, Presentation and Application.

Important Questions

1. Explain all seven OSI layers.

2. What is encapsulation?

3. Differentiate the network and transport layers.

Chapter 5: TCP/IP Model

5.1 Introduction

The TCP/IP protocol suite provides the foundation for communication across the Internet and many private networks.

5.2 Application Layer

This layer includes protocols used by applications, such as HTTP, DNS, SMTP and DHCP.

5.3 Transport Layer

The transport layer provides communication between application processes. TCP offers a reliable, ordered byte stream, while UDP provides datagrams without built-in delivery guarantees.

5.4 Internet Layer

The Internet layer handles IP addressing and packet delivery across interconnected networks. IP does not itself guarantee delivery or ordering.

5.5 Network Access Layer

This layer covers communication over the local network medium, including technologies such as Ethernet and Wi-Fi.

5.6 OSI and TCP/IP Comparison

The OSI model has seven layers. A common four-layer TCP/IP teaching model combines the OSI session, presentation and application functions into the application layer and combines the physical and data link functions into the network access layer.

5.7 Encapsulation in TCP/IP

Application data is passed to the transport layer, then carried in IP packets and transmitted through a link-layer technology.

Practical Example / Application: When a browser requests a web page, HTTP or HTTPS operates at the application level, TCP may carry the connection, IP routes packets and Ethernet or Wi-Fi carries them across a local link.

Important Questions

1. Explain the TCP/IP model.

2. Compare OSI and TCP/IP.

3. Explain the role of the Internet layer.

Chapter 6: Physical Layer

6.1 Main Function

The physical layer is concerned with transmitting bits through a physical or wireless medium.

6.2 Signals

Data can be represented using electrical, optical or radio signals. Signal characteristics affect how information is transmitted.

6.3 Analog and Digital Signals

Analog signals vary continuously, while digital signals represent information using discrete values.

6.4 Bandwidth

Bandwidth can describe a frequency range or a link's nominal data capacity, depending on context. Data rates are commonly expressed in bits per second.

6.5 Transmission Modes

  • Simplex: Communication in one direction.
  • Half-Duplex: Both directions are supported, but not simultaneously.
  • Full-Duplex: Both directions can operate simultaneously.

6.6 Transmission Impairments

Attenuation, noise and distortion can affect signal quality and communication reliability.

6.7 Multiplexing

Multiplexing combines multiple signals or data streams for transmission over a shared medium. Examples include frequency-division and time-division multiplexing.

Practical Example / Application: Full-duplex Ethernet allows devices to send and receive data simultaneously over a suitable connection.

Important Questions

1. Explain simplex, half-duplex and full-duplex.

2. Differentiate analog and digital signals.

3. What is multiplexing?

Chapter 7: Data Link Layer

7.1 Main Functions

The data link layer supports communication across a single network link. Functions may include framing, MAC addressing, error detection and media access control.

7.2 Framing

Framing organises transmitted data into identifiable units called frames.

7.3 MAC Address

A MAC address identifies a network interface at the data link layer. Ethernet commonly uses 48-bit MAC addresses.

7.4 Error Detection

Techniques such as checksums and cyclic redundancy checks can help detect transmission errors. Error detection does not necessarily correct errors.

7.5 Flow Control

Flow control helps prevent a sender from overwhelming a receiver when a protocol provides this function.

7.6 Media Access Control

Media access control rules determine how devices share a communication medium. Different technologies use different mechanisms.

7.7 Ethernet Frames

An Ethernet frame contains fields such as destination MAC address, source MAC address, type or length information, payload and frame check sequence.

Practical Example / Application: A switch examines destination MAC addresses to forward Ethernet frames toward the appropriate network port.

Chapter 8: Ethernet and Switching

8.1 Ethernet

Ethernet is a widely used family of wired networking technologies standardised by IEEE 802.3.

8.2 Ethernet Addressing

Ethernet frames use source and destination MAC addresses for communication across a local Ethernet network.

8.3 How a Switch Learns Addresses

A learning switch examines the source MAC address of incoming frames and records the associated port in its forwarding database.

8.4 Frame Forwarding

When a destination MAC address is known, a switch can forward the frame to the appropriate port. Unknown destinations may be flooded within the relevant VLAN, subject to normal forwarding rules.

8.5 Broadcast and Collision Domains

Switch ports normally separate collision domains. Broadcast traffic is generally limited by VLAN boundaries unless a device or configuration forwards it between networks.

8.6 VLAN

A Virtual Local Area Network divides a switched network into separate logical broadcast domains. VLANs can support network segmentation and administration.

8.7 Switching Loops and STP

Redundant Layer 2 links can create loops. Spanning Tree Protocol helps prevent forwarding loops in supported bridged networks.

Practical Example / Application: A college may use separate VLANs for student computers, staff computers and administrative systems.

Important Questions

1. Explain the working of an Ethernet switch.

Chapter 9: Network Layer and IP

9.1 Network Layer

The network layer enables packets to travel between different IP networks using logical addressing and routing.

9.2 Internet Protocol

IP provides addressing and packet delivery across interconnected networks. IPv4 and IPv6 are the two principal versions used on the Internet.

9.3 IPv4

IPv4 uses 32-bit addresses, usually written as four decimal octets separated by dots.

Example IPv4 address:
192.168.1.10

9.4 Public and Private Addresses

Public addresses are globally routable under applicable Internet routing policies. Private IPv4 address ranges are intended for internal networks and are not globally routed as ordinary public destinations.

9.5 Packet Forwarding

A router examines a packet's destination IP address and uses its routing table to choose a next hop or outgoing interface.

9.6 Default Gateway

A default gateway is the router or other Layer 3 device that a host uses to reach destinations outside its directly connected network when no more specific route applies.

9.7 ICMP

Internet Control Message Protocol supports network diagnostic and error-reporting functions. The ping utility commonly uses ICMP echo messages where permitted.

Practical Example / Application: A laptop on a home network sends traffic for an external website through its configured default gateway.

Important Questions

1. Explain the network layer.

2. Differentiate public and private IPv4 addresses.

Chapter 10: IPv4 Addressing and Subnetting

10.1 IPv4 Address Structure

An IPv4 address contains 32 bits. A subnet mask identifies which bits represent the network prefix and which bits represent the host portion.

10.2 CIDR Notation

Classless Inter-Domain Routing notation writes an address followed by a slash and the number of prefix bits.

Example:
192.168.1.0/24

Network prefix: 24 bits
Host portion: 8 bits

10.3 Subnet Mask

The subnet mask represents the network prefix using binary ones, followed by zeros for the host portion.

/24 subnet mask:
255.255.255.0

10.4 Network and Broadcast Addresses

For a conventional IPv4 subnet with a prefix from /0 through /30, the network address has all host bits set to zero and the directed broadcast address has all host bits set to one. Special cases such as /31 point-to-point links and /32 host routes have different usage rules.

10.5 Number of Addresses

For a conventional subnet with h host bits, the total number of IPv4 addresses is 2h. In the usual subnetting case, two addresses are reserved for the network and broadcast addresses.

Example: For 192.168.1.0/24, there are 256 total addresses. In a conventional broadcast subnet, 254 addresses are available for hosts.

10.6 Subnetting

Subnetting divides an IP address block into smaller network prefixes. It can help organise networks, manage address allocation and separate broadcast domains.

10.7 Variable-Length Subnet Masking

VLSM allows subnets of different sizes to be allocated from an address block according to their requirements.

Chapter 11: IPv6 Addressing

11.1 Need for IPv6

IPv6 was developed to provide a much larger address space and support the continued growth of Internet-connected devices.

11.2 IPv6 Address Structure

IPv6 uses 128-bit addresses, commonly written as eight groups of hexadecimal digits separated by colons.

Example:
2001:db8:1234:0000:0000:0000:0000:0001

11.3 Address Shortening

Leading zeros within a group may be omitted. One consecutive run of all-zero groups can be compressed using a double colon (::) in a single address.

Expanded:
2001:0db8:0000:0000:0000:0000:0000:0001

Shortened:
2001:db8::1

11.4 IPv6 Address Types

  • Unicast: Identifies an interface for one-to-one delivery.
  • Multicast: Identifies a group of interfaces.
  • Anycast: Identifies a group of interfaces where routing delivers traffic to an appropriate member, commonly the nearest according to routing.

11.5 IPv6 Features

IPv6 provides a substantially larger address space and simplifies some aspects of the base header. It also supports stateless address autoconfiguration and uses Neighbor Discovery for local-link functions.

11.6 IPv4 and IPv6

IPv4 uses 32-bit addresses, whereas IPv6 uses 128-bit addresses. Their packet formats and supporting mechanisms differ, so transition and coexistence technologies may be required.

Practical Example / Application: IPv6 enables networks to assign addresses from a vastly larger address space than IPv4.

Important Questions

Chapter 12: Routing and Routing Protocols

12.1 What is Routing?

Routing is the process of determining paths through which packets can travel from one network to another.

12.2 Routing Table

A routing table contains destination prefixes and information such as next hops, outgoing interfaces and route metrics.

12.3 Static Routing

Static routes are manually configured by an administrator. They can be useful in small or predictable networks.

12.4 Dynamic Routing

Dynamic routing protocols allow routers to exchange information and update routes as network conditions change.

12.5 Distance Vector Routing

Distance vector protocols exchange route information using metrics that describe distance to destinations. RIP is a classic example.

12.6 Link State Routing

Link state protocols build a view of network topology and calculate paths using a shortest-path algorithm. OSPF is a common example.

12.7 Border Gateway Protocol

BGP exchanges routing information between autonomous systems and is a major routing protocol used on the global Internet.

12.8 Routing Metrics

Routing decisions may consider hop count, bandwidth-related costs, delay, administrative preferences and other protocol-specific metrics.

Practical Example / Application: When a router receives a packet for a remote network, it consults its routing table to decide where to forward it.

Important Questions

Chapter 13: Transport Layer — TCP and UDP

13.1 Transport Layer

The transport layer supports communication between application processes on different devices.

13.2 Port Numbers

Port numbers help identify application services or communication endpoints. TCP and UDP maintain separate port-number spaces.

13.3 TCP

Transmission Control Protocol provides a reliable, ordered byte stream. It uses mechanisms such as acknowledgements, retransmission, flow control and congestion control.

13.4 TCP Connection Establishment

TCP commonly establishes a connection using a three-way handshake involving SYN, SYN-ACK and ACK segments.

13.5 UDP

User Datagram Protocol provides message-oriented datagram delivery without TCP-style built-in reliability, ordering or connection establishment.

13.6 TCP vs UDP

  • TCP provides reliable, ordered byte-stream delivery.
  • UDP sends independent datagrams with minimal protocol overhead.
  • TCP is commonly used for web and file-transfer connections.
  • UDP is commonly used where applications benefit from datagrams, such as DNS queries, voice and real-time communication, depending on the protocol.

13.7 Flow and Congestion Control

Flow control protects the receiver from being overwhelmed by incoming data. Congestion control helps manage the load placed on the network.

Practical Example / Application: An application that transfers a file may use TCP to obtain reliable ordered delivery, while a real-time application may use UDP when its design benefits from lower protocol overhead and handles loss itself.

Chapter 14: Application Layer Protocols

14.1 HTTP and HTTPS

HTTP is used to transfer web resources. HTTPS protects HTTP communication using TLS, which provides encryption and server authentication when correctly configured.

14.2 Domain Name System (DNS)

DNS translates domain names into records such as IP addresses. It allows users to access services through names rather than remembering numeric addresses.

14.3 Dynamic Host Configuration Protocol

DHCP automatically provides network configuration information, which may include an IP address, subnet mask, default gateway and DNS servers.

14.4 File Transfer Protocol

FTP is a protocol for transferring files. Traditional FTP does not protect credentials or data through encryption, so secure alternatives may be preferable.

14.5 Email Protocols

  • SMTP: Used to send or relay email.
  • IMAP: Allows clients to access and manage email stored on a server.
  • POP3: Supports retrieval of email from a server.

14.6 SSH

Secure Shell provides encrypted remote login and other secure communication functions.

14.7 SNMP

Simple Network Management Protocol supports monitoring and management of network devices.

14.8 Common Ports

  • HTTP: TCP port 80.
  • HTTPS: TCP port 443; HTTP/3 uses QUIC over UDP port 443 by default.
  • DNS: Port 53, commonly using UDP or TCP depending on the operation.
  • SSH: TCP port 22.
  • SMTP submission: Commonly TCP port 587.
  • DHCP for IPv4: UDP ports 67 and 68.
Practical Example / Application: When a user enters a website name, DNS may resolve the name and the browser then uses HTTP over a suitable secure or non-secure transport.

Important Questions

Chapter 15: Wireless and Mobile Networks

15.1 Wireless Networking

Wireless networking transmits information without requiring a physical cable between communicating devices.

15.2 Wi-Fi

Wi-Fi is based on IEEE 802.11 wireless networking standards. It is widely used in homes, offices, colleges and public access networks.

15.3 Wireless Access Point

An access point connects wireless clients to a local network. Home wireless routers often combine an access point with routing and switching features.

15.4 Bluetooth

Bluetooth supports short-range wireless communication between devices such as headphones, keyboards, phones and computers.

15.5 Cellular Networks

Cellular networks provide mobile communication through a system of radio access equipment and a core network. Technologies include 4G LTE and 5G.

15.6 Wireless Security

Wireless networks should use suitable modern security settings, strong credentials and updated equipment. WPA2 and WPA3 are widely used Wi-Fi security technologies.

15.7 Wireless Challenges

Wireless networks may experience interference, signal attenuation, congestion, limited coverage and variable throughput.

Practical Example / Application: A smartphone can connect to a home Wi-Fi network for local connectivity and use a cellular network when Wi-Fi is unavailable.

Important Questions

1. Explain Wi-Fi and Bluetooth.

2. What is a wireless access point?

3. Explain the advantages and limitations of wireless networking.

Chapter 16: Network Security and Troubleshooting

16.1 Network Security

Network security protects systems, communication and data against unauthorised access, disruption and modification.

16.2 Confidentiality, Integrity and Availability

  • Confidentiality: Information is available only to authorised parties.
  • Integrity: Information remains accurate and protected against unauthorised changes.
  • Availability: Services and information remain accessible when required.

16.3 Firewall

A firewall applies traffic rules to allow or block network communications according to its configuration.

16.4 Encryption

Encryption transforms readable information into a protected form using cryptographic methods. Secure network protocols use encryption to protect information in transit.

16.5 Authentication and Access Control

Authentication verifies identity, while access control limits what users and systems are permitted to do.

16.6 Common Network Problems

  • Incorrect IP configuration.
  • Disconnected cables or weak wireless signals.
  • Incorrect default gateway.
  • DNS resolution problems.
  • Firewall rules blocking required traffic.
  • Network congestion or service outages.

16.7 Basic Troubleshooting Commands

Windows:
ipconfig
ping
tracert
nslookup
netstat

Linux:
ip addr
ip route
ping
traceroute
nslookup
ss

Command availability varies by operating system. Use troubleshooting commands only on systems and networks you are authorised to inspect.

16.8 Troubleshooting Method

Identify the problem, check physical connectivity, inspect IP configuration, test local and remote reachability, check name resolution and review relevant device or service settings.

Practical Example / Application: If a computer can reach a website by IP address but not by domain name, checking DNS configuration may help identify the cause.

Chapter 17: Cloud, Virtual and Modern Networks

17.1 Virtualization

Network virtualization creates logical network resources using software. It allows network configurations to be managed independently of some underlying physical details.

17.2 Virtual Machines and Virtual Networks

Virtual machines can use virtual network interfaces connected to virtual switches, virtual networks or physical network adapters.

17.3 Cloud Networking

Cloud platforms provide virtual networks, subnets, routing, gateways, load balancers and security controls.

17.4 Software-Defined Networking

Software-Defined Networking (SDN) separates aspects of network control from packet forwarding to make network behaviour more programmable and centrally manageable.

17.5 Network Function Virtualization

Network Function Virtualization (NFV) implements certain network functions as software rather than relying exclusively on dedicated hardware appliances.

17.6 Internet of Things

The Internet of Things connects physical devices equipped with sensors, software and network connectivity. These devices can exchange information with applications and other systems.

17.7 Content Delivery Networks

A Content Delivery Network (CDN) distributes content across multiple locations to improve availability and reduce delivery latency for users.

Practical Example / Application: A cloud-hosted website may use a virtual network, firewall rules and a load balancer to connect users to its application servers.

Important Questions

1. Define network virtualization.

2. Explain SDN and NFV.

3. What is cloud networking?

4. Explain the role of a CDN.

Glossary

  • Bandwidth: A measure of link capacity or frequency range, depending on context.
  • Client: A device or application that requests a service.
  • DNS: Domain Name System.
  • DHCP: Dynamic Host Configuration Protocol.
  • Ethernet: A family of wired networking technologies.
  • Firewall: A system that controls network traffic using rules.
  • IP Address: A logical address used by the Internet Protocol.
  • IPv4: Internet Protocol version 4, using 32-bit addresses.
  • IPv6: Internet Protocol version 6, using 128-bit addresses.
  • LAN: Local Area Network.
  • MAC Address: A link-layer address used by technologies such as Ethernet.
  • OSI: Open Systems Interconnection.
  • Packet: A unit of data carried by a network-layer protocol.
  • Protocol: Rules governing communication between systems.
  • Router: A device that forwards packets between networks.
  • Subnet: A logically defined portion of an IP network.
  • TCP: Transmission Control Protocol.
  • UDP: User Datagram Protocol.
  • VLAN: Virtual Local Area Network.
  • WAN: Wide Area Network.
  • Wi-Fi: Wireless networking technology based on IEEE 802.11 standards.
